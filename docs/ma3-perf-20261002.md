## Benchmark changes and validation

`driver/bench_ma3_perf.c` now rejects malformed/out-of-range filters and
empty selections, reports selected case counts, and supports `--list` without
rendering. The full matrix has 2,880 cases / 5,760 determinism-pass rows;
fixing limit 32 gives 960 cases / 1,920 rows. This run measured a subset.

Optional `MA3_PERF_RAW` records chronological CPU/wall samples, process/case
IDs, block-endpoint active/held/sustained/released slot counts, phase and
deadline misses. Raw output refuses to overwrite an existing file. Summary
quantiles use documented nearest-rank indexing; diagnostics explicitly include
warmup. Output errors return failure. The empty-bracket mode measures the
same nested clock sequence without rendering; no overhead is subtracted.

Only `ma_voice_pool_render` is timed. Initialization, event dispatch,
allocation, occupancy scans, PCM hashing and output are outside its brackets.
The PCM hash includes warmup. Additional observation can affect surrounding
cache/scheduling conditions, so later A/B variants must share this harness.

Validation evidence:

- Full GCC native suite and release freestanding-symbol audit passed.
- Seven focused benchmark CLI tests passed with the final GCC, Clang and
  Clang ASan/UBSan/float-cast-overflow binaries. These cover strict filters,
  matrix counts, raw/summary consistency, sustain/release entry, idle and
  sparse/unison slot counts, output preservation and clock-bracket shape.
- Original and final revised harnesses produced identical PCM and effect
  fingerprints in 160 short rows: five patches, BCS off/on, all eight
  scenarios, two determinism passes, wet, 32-slot limit, 128 frames,
  two warmup and four measured blocks. These were functional checks only.
- Independent review recomputed every measured summary from raw samples and
  verified 50 source/build identities and 22 measured source snapshots.

The existing native suite was run before the last reporting-only fixes;
the final harness received all seven focused tests in each of the three
verification builds and the final 160-row equivalence comparison. DSP files
did not change. Full release-to-sleep/tail and controller-stress measurement
coverage remains work for the later acceptance batch.

## Release results

Recipe: 64 warmup and 256 measured blocks per pass; two in-process
determinism passes per case; two separate process epochs. Full and one-slot
scenario order was reversed between epochs. All five patches, BCS off/on,
wet, limit 32, 48 kHz, 128 frames were included in each scenario.

The 80 summary rows contain 20,480 measured blocks. Each full-case row below
combines four pass summaries; ranges are observed CPU means, not confidence
intervals or steady-state estimates. Each case has 1,024 measured blocks.

| Patch | BCS | CPU mean range, ms | CPU / wall misses |
| --- | ---: | ---: | ---: |
| Tepih | 0 | 8.729–12.469 | 1,024 / 1,024 |
| Tepih | 1 | 11.573–14.283 | 1,024 / 1,024 |
| Lead | 0 | 8.928–11.145 | 1,024 / 1,024 |
| Lead | 1 | 11.852–14.026 | 1,024 / 1,024 |
| Raster | 0 | 7.610–7.966 | 1,024 / 1,024 |
| Raster | 1 | 8.741–11.469 | 1,024 / 1,024 |
| Prizma | 0 | 10.593–12.796 | 1,024 / 1,024 |
| Prizma | 1 | 11.638–14.699 | 1,024 / 1,024 |
| Granica | 0 | 11.008–12.812 | 1,024 / 1,024 |
| Granica | 1 | 11.847–13.379 | 1,024 / 1,024 |

All 10,240 full-case blocks missed both CPU and wall deadlines of 2.667 ms;
32 held slots remained active at every observed block endpoint. One-slot
cases retained one held slot, had zero CPU misses, and 241 wall misses out
of 10,240 blocks. PCM hashes matched across epochs and passes for each case.
No measured case reported sanitization, effect clipping, output knee hits or
ladder resets; tiny-flush counts were deterministic (4–31).

The host was noisy. The empty CPU bracket ranged 0.678–2.811 us (mean
0.848 us), while the empty wall bracket reached **5.511 ms**. Full-case wall
p99 varied as high as 87.581 ms. These observations support a large budget
gap, but not precise small-speedup claims or a supported live envelope.
Readable CPU-frequency snapshots also varied; neither frequency locking nor
thermal convergence was established. With only 0.171 s of modeled warmup
and 0.683 s measured audio per pass, envelopes and wet histories can still
evolve. Blocks and in-process passes are not independent statistical trials.

Per-case CPU/wall p50/p99/max, diagnostics, raw chronological samples and
sparse results remain in `release-case-table.csv`, `release-summary.md` and
the four `epoch*-raw.csv` files under the run directory.

## Attribution and next experiment

Eight separate Gprof runs cover full Tepih/Raster/Lead with BCS off/on and
one-slot Tepih with BCS off/on. Lead BCS1 had the largest CPU mean averaged
over its four release passes, which is the recorded selection criterion.
Prizma BCS1 had the largest individual pass mean. Variation is too large to
claim a stable worst-patch ordering.

Gprof profiles the whole process, including warmup, initialization, hashing
and output. Its flat table also misnames some compiler-generated clones:
for example, the apparent Tepih `raster_table_sample` bucket actually covers
`poly_blep.part.0`. The saved offline `map_profile_histogram.py` maps raw
histogram addresses to exact binary symbol ranges. Independent review checked
the format, bin boundaries, counts and all eight inputs. The original Gprof
reports remain preserved; their misleading helper names are not used as stage
cost evidence.

Corrected full-case **instrumented direct self samples** put `synth_tick`
at roughly 41–59%, with BCS derivative calls around 4–5% when BCS is on.
About 1–4% of full-case samples remain outside identified symbol ranges.
These are neither release-time shares nor propagated call-graph estimates.
FIR, ladder, prewarp and other inlined work remain inseparable inside
`synth_tick`; the sparse profiles contain only 17/34 samples and do not
support detailed rankings.

The first bounded candidate is **split circular FIR traversal**. Current
release assembly retains a wrap/index branch per tap in the six 31-tap
decimations per output sample/voice. Splitting traversal at the ring boundary
can remove repeated wrap work while retaining every tap, coefficient order,
multiply/add order and state layout. Zero-tap removal, symmetric pairing and
reassociation are outside this exact-equivalence experiment.

This selection combines a large parent bucket, confirmed generated index work
and a small state-proof surface; it does not establish a separate FIR cost
share or predict a speedup. The real benefit must be measured with matched
A/B binaries under quieter conditions. BCS invariant preparation is a second
candidate with a smaller directly attributed component; control caches need
more extensive invalidation proof. Shared-effect or pool-bookkeeping rewrites
are not the first full-pool candidates supported by this batch.

Next work is P3's matched Raster investigation and P4's isolated FIR
experiment, with pinned PCM/hidden-state, compiler, sanitizer and numerical
gates before release A/B measurement. The present result does not establish
that exact optimizations can close the several-fold performance gap.

## Reproduction and artifact boundary

The run-specific utility is `test/ma3_perf_measure.py`. Its `prepare` action
requires an already frozen P0 run directory and `source-before/` snapshot;
it builds release, Clang, sanitizer and Gprof variants and records commands.
It does not bootstrap a new P0 snapshot. Completed measurement commands were:

```sh
python3 test/ma3_perf_measure.py run --cpu 0
python3 test/ma3_perf_measure.py summarize
```

The default directory is this named run. Do not rerun `prepare` or `run`
there: outputs are preserved with exclusive-create semantics. A new run
needs its own frozen source directory and `--directory` argument. Actual
build commands and per-process commands/environment are retained in
`*-command.json` and `executed-recipe.json`; no dependency install or host
tuning was performed.

Primary artifacts are the source/build manifests, raw and summary CSVs,
eight profile directories with `gmon.out` and `gprof.txt`, targeted release
assembly, `dsp-analysis.md`, correctness logs, and `independent-review.md`.
Generated data stays under ignored `build/`; this document records the
result without treating local artifacts as committed source.

The lab evidence-pack collector indexed every one of the 161 run files
present at collection time, including raw CSVs, profiles and independent
review. `evidence-pack.json` and `evidence-pack-check.json` retain the inventory
and coverage check. This is a path inventory, not a separate archival copy.
